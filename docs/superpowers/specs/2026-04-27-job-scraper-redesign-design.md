# 招聘抓取链路重构设计

## 1. 背景与目标

当前项目的核心问题不是站点本身不可抓，而是抓取架构过重：

- `智联招聘` 依赖 Playwright 打开列表页，再逐条访问详情页抓 JD。
- `牛客网` 依赖前端城市级联筛选器和页面点击交互。
- GitHub Actions 需要安装和启动浏览器，运行时间长，失效面大。

在保持以下业务约束不变的前提下，需要重构抓取链路：

- 站点固定为：`智联招聘`、`牛客网`
- 城市固定为：`杭州`、`上海`、`南京`
- 城市优先级：`杭州 > 上海 > 南京`
- 岗位范围从单一“数据分析实习”扩展为同岗位族实习岗
- 每日目标为：`飞书最终写入约 450 条`
- GitHub Actions 单次运行时长控制在 `30 分钟内`

## 2. 范围

### 2.1 站点范围

- 保留：`智联招聘`
- 保留：`牛客网`
- 不新增其他招聘网站

### 2.2 城市范围

- `杭州`
- `上海`
- `南京`

### 2.3 岗位范围

核心岗位词：

- `数据分析`
- `商业分析`
- `经营分析`
- `数据运营`
- `数据产品分析`
- `用户研究`

补充岗位词：

- `增长分析`
- `策略分析`
- `用户分析`
- `商业数据分析`

岗位类型限定：

- 仅保留 `实习 / 实习生 / 暑期实习 / 日常实习` 相关职位

## 3. 总体方案

采用 `HTTP 主抓 + 浏览器仅保留为本地调试兜底` 的方案。

线上定时任务只走轻量链路：

- `智联招聘` 作为主抓源，直接请求搜索页 HTML，解析页面内嵌的 SSR 数据。
- `牛客网` 作为补量源，使用查询词组合抓取搜索结果，再请求少量详情页 HTML。
- 最终统一清洗、去重、打分、截断到约 `450` 条，再同步到飞书。

浏览器自动化不再作为 GitHub Actions 的正式运行链路，只保留本地调试价值。

## 4. 抓取架构

### 4.1 智联招聘主抓链路

抓取方式：

- 请求搜索页 HTML，例如：
  - `https://www.zhaopin.com/sou/?jl=<city_code>&kw=<keyword>&p=<page>&et=4`
- 从页面中提取 `__INITIAL_STATE__`
- 解析其中的：
  - `positionList`
  - `positionCount`
  - `pages`

关键结论：

- 列表页中的 `positionList` 已携带职位卡片数据
- 列表数据中已包含完整或足够完整的 JD 信息：
  - `jobDetailData.position.desc.description`
- 因此不再逐条访问详情页

输出字段：

- 岗位名称
- 公司名称
- 薪资
- 工作地点
- 岗位描述
- 岗位类型
- 来源平台
- 原始职位 ID / URL
- 发布时间
- 城市
- 关键词命中信息

### 4.2 牛客网补量链路

抓取方式：

- 不再依赖城市级联筛选器点击
- 改为按查询词直接请求搜索页，例如：
  - `数据分析 实习 杭州`
  - `商业分析 实习 杭州`
  - `数据运营 实习 上海`
- 从搜索结果页提取职位详情链接
- 仅对必要的少量详情页发起 HTML 请求
- 从详情页正文中提取：
  - 岗位职责
  - 岗位要求
  - 公司名
  - 工作地点
  - 薪资

使用原则：

- 牛客不再承担主抓流量
- 仅在智联去重后无法满足最终目标时补量

### 4.3 统一调度链路

主程序执行顺序：

1. 抓取智联核心候选池
2. 评估距离目标 `450` 的缺口
3. 若缺口存在，则抓取牛客补量池
4. 合并原始结果
5. 清洗、去重、排序
6. 截断到约 `450` 条
7. 保存 CSV
8. 通过质量校验后同步飞书

## 5. 配额控制

### 5.1 目标口径

`450` 指的是：

- 清洗去重后
- 实际写入飞书的最终条数

不是原始抓取总数。

### 5.2 候选池目标

为了抵抗跨关键词、跨平台重复，不能直接以 `450` 为原始抓取目标。

建议：

- 原始候选池目标：`650-800`
- 最终写入目标：`450`

### 5.3 页数策略

页数不采用“全部组合固定翻到底”，而采用“先铺首屏，再按缺口补页”。

#### 智联招聘优先级

城市优先级：

1. `杭州`
2. `上海`
3. `南京`

#### 推荐页数预算

杭州：

- `数据分析`：`3-4` 页
- `数据运营`：`2-3` 页
- `商业分析 / 经营分析 / 数据产品分析 / 用户研究`：默认 `1` 页，不足时升到 `2` 页

上海：

- `数据分析`：`2-3` 页
- `数据运营`：`1-2` 页
- 其他词：默认 `1` 页

南京：

- `数据分析`：`1-2` 页
- `数据运营`：`1` 页
- 其他词：默认 `1` 页，仅在候选池不足时使用

#### 补页顺序

1. `杭州` 全部核心词第 1 页
2. `上海` 全部核心词第 1 页
3. `南京` 全部核心词第 1 页
4. 若候选池不足，按顺序补页：
   - `杭州-数据分析`
   - `杭州-数据运营`
   - `上海-数据分析`
   - `杭州-商业分析`
   - `杭州-经营分析`
   - `上海-数据运营`
   - `南京-数据分析`

## 6. 去重与排序

### 6.1 去重策略

分三层去重：

1. 平台原始 ID 去重
   - 智联：`positionNumber / positionURL`
   - 牛客：`jobs/detail/<id>`
2. 跨关键词去重
   - 同一职位被多个查询词命中时合并
3. 跨平台业务去重
   - 键：`公司名称 + 岗位名称 + 标准化城市`

### 6.2 排序策略

排序因子：

1. 标题命中核心词优先
2. 标题命中补充词次之
3. 仅 JD 命中再次之
4. 明确实习标签优先
5. 发布时间新优先
6. JD 完整度高优先
7. 公司重复数量过高时降权

### 6.3 公司重复软限制

为避免单一公司大量重复岗位占满结果集，需要设软上限：

- 同公司同类岗位可保留多条
- 但在最终 `450` 条中限制单公司过度集中

## 7. 错误处理

### 7.1 请求级错误

适用情况：

- 超时
- 403
- 429
- 5xx

处理方式：

- 短重试
- 指数退避
- 限制最大重试次数
- 单页失败不拖垮整轮任务

### 7.2 数据源级错误

适用情况：

- 智联页面结构变化
- 牛客详情页正文结构失效
- 某平台整体返回异常

处理方式：

- 标记平台级失败
- 继续执行其他平台
- 最终由质量门槛决定是否允许同步飞书

### 7.3 结构校验

智联需校验：

- `positionList`
- `positionCount`
- `pages`

牛客需校验：

- 岗位标题
- 公司名称
- 正文职责/要求区域

缺少关键字段的记录不进入最终结果集。

## 8. 质量门槛与飞书同步

### 8.1 当前问题

当前项目会在同步前清空飞书旧记录。如果当天抓取异常，这会把飞书表覆盖成低质量数据。

### 8.2 改进原则

仍保留“全量覆盖”业务模式，但加质量门槛。

### 8.3 同步前检查

建议增加：

- 最低有效数门槛
  - 例如最终合格结果 `< 250` 时，不覆盖飞书
- 主源健康门槛
  - 智联结果过低时，判定主抓异常
- 城市分布门槛
  - 若 `杭州` 结果异常偏少，标记为低质量

### 8.4 同步流程

1. 抓取与清洗
2. 生成最终结果集
3. 保存本地 CSV
4. 通过质量门槛检查
5. 仅在通过时：
   - 清空飞书旧记录
   - 批量写入新记录
6. 若未通过：
   - 不改飞书
   - 输出日志与 artifact
   - 任务失败退出

## 9. GitHub Actions 策略

### 9.1 保留内容

- Python 环境安装
- 依赖缓存
- 主程序执行
- CSV artifact 上传

### 9.2 删除内容

- Playwright 浏览器缓存
- `playwright install chromium`
- `playwright install-deps chromium`

### 9.3 新增内容

- 日志 artifact
- 失败时也上传原始/最终 CSV
- `timeout-minutes: 30`
- 当质量门槛不满足时返回失败状态

### 9.4 预期时长

常态：

- `15-22` 分钟

高负载日：

- `25-30` 分钟

## 10. 配置变更

### 10.1 配置新增

建议新增配置项：

- `TARGET_FINAL_COUNT = 450`
- `TARGET_CITIES_PRIORITY`
- `KEYWORD_GROUPS`
- `ZHILIAN_PAGE_PLAN`
- `NOWCODER_QUERY_PLAN`
- `MIN_VALID_RESULT_COUNT`
- `REQUEST_TIMEOUT`
- `MAX_RETRIES`
- `CONCURRENCY_LIMIT`

### 10.2 配置废弃

以下配置不再作为线上主链路关键项：

- 浏览器超时
- 浏览器滚动次数
- 随机长等待
- 牛客城市级联筛选配置

### 10.3 安全要求

飞书配置必须改为：

- 仅从环境变量读取
- 不再保留任何默认密钥

当前 `config.py` 中的飞书硬编码凭据属于必须移除的风险项。

## 11. 代码结构调整

### 11.1 `scrapers/zhilian.py`

改造为：

- HTTP 请求 + SSR 解析
- 不使用 Playwright
- 不逐条打开详情页

### 11.2 `scrapers/nowcoder.py`

改造为：

- 查询词组合搜索
- 搜索页解析详情链接
- 仅对必要详情页发 HTML 请求

### 11.3 `scrapers/base.py`

改造为：

- 通用 HTTP Session / 重试 / 请求头工具
- 不再承担浏览器基类职责

### 11.4 `cleaner.py`

保留并增强：

- 城市标准化
- 技术关键词提取
- 业务关键词提取
- 跨平台去重
- 排序打分
- 最终截断到 `450`

### 11.5 `main.py`

改造为三阶段调度：

1. 智联主抓
2. 牛客补量
3. 清洗、校验、同步

### 11.6 `utils.py`

调整为：

- 文本清洗
- 日期解析
- 重试退避
- 轻量抖动

移除：

- 浏览器滚动模拟
- 仅为页面自动化服务的行为模拟逻辑

## 12. 测试策略

至少补三类测试：

### 12.1 解析测试

- 智联搜索页 HTML 样本解析测试
- 牛客详情页 HTML 样本解析测试

### 12.2 清洗测试

- 城市标准化测试
- 去重测试
- 截断到 `450` 的稳定性测试

### 12.3 调度测试

- 智联不足时触发牛客补量
- 质量门槛不满足时不覆盖飞书

## 13. 非目标

本次重构不做：

- 新增第三方招聘网站
- 建立长期历史岗位仓库
- 引入数据库存储层
- 为线上任务保留浏览器执行链路

## 14. 设计结论

本次重构的本质不是“修选择器”，而是把项目从：

- `浏览器自动化抓取项目`

重构为：

- `HTTP/SSR 抓取 + 配额控制 + 质量门槛同步项目`

在当前业务约束下，这是唯一同时满足以下目标的合理方案：

- `3 个固定城市`
- `2 个固定网站`
- `杭州优先`
- `最终写入约 450 条`
- `30 分钟内完成`
- `GitHub Actions 稳定运行`
